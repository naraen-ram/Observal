# Remaining component-insights gates: Cursor, Codex, Kiro

**2026-10-17; stacked draft PR #3.** These are *conditional engineering estimates*, not support promises or evidence of zero use. They cover one tested version/scope at a time, including sanitized tests and isolated live acceptance, **after** necessary account or IDE access is available. Upstream product changes and CI/human-review time are not estimable. The verified-presence and permissions contract remains on draft #1779. No original home, original checkout, production endpoint, raw prompts, arguments, results, tokens, or transcripts were used as PR artifacts.

## New native controls and stop conditions

| Runtime | Controlled finding | Decision before an opt-in |
| --- | --- | --- |
| **Kiro CLI 2.32.0**, isolated tracked project stdio pin | An inline v2-agent `preToolUse` hook receives native `tool_name: @matrix-mcp-probe/ping` and `session_id`; a *successful* inert call additionally fires `postToolUse` with that same alias and writes an independent server marker. The native four-line session still calls its tool only `ping`, but contains a linked `toolResult` with `status: success`. With noninteractive approval denied, `preToolUse` fired, `postToolUse` did not, and the native result was `error`. A two-line no-tool session fired neither tool hook. A later **two-server/same-`ping`** control loaded a separately marked, untracked alias beside the verified pin: only that alias's marker fired; the pre/post hook named that alias, while a fresh four-line session automatically arrived with the original pin verified. These are **separate** installation, hook and native-transcript facts. The hook input has **no tool-use ID or explicit result status**, and its alias/outcome were not part of the canonical session source. | This is a promising **native hook signal**, **not** a published use cell. A transient probe marker, a verified pin for the *other* alias, or a generic transcript `ping` cannot be matched as a complete source call. Do not attribute multiple same-tool calls by order/time or count a no-hook session as zero. |
| **Cursor Agent 2026.10.14-941492e**, tracked project/user stdio pins | Reauthenticated only the temporary home using the CLI's file credential store. **Actual native hooks fired** in approved, rejected, server-error, no-tool and two-server/same-`ping` controls. `beforeMCPExecution` and `afterMCPExecution` supplied the exact server/tool, version, session/conversation IDs and the **same `tool_use_id`**; `postToolUse` carried the same ID but only `MCP:ping`, including on rejection/error, so it is **not** a success signal. The after-hook's parsed `result_json` was `{rejected: true, reason: …}` for an attempt with no marker; `{content: […], isError: false}` for an independently marked success; and `{content: […], isError: true}` for a marked inert server error. Two aliases exporting `ping` wrote different markers and were distinguished by hook server name and call ID. Native JSONL itself still stored attempts, not outcomes. Fresh project no-tool/approved/denied/error/collision and fresh user-scope approved sessions arrived automatically with verified pins before reconcile. An initial user-scope delivery was blocked by an **expired temporary Observal token**; it was not counted as automatic acceptance, and a newly pinned, fresh-token run established that scope. Hook input and full result were **never persisted**: private scratch retained only structural fields, strict boolean flags and one-way ID digests. | The **native identity, call pairing and result distinction are now proven on this exact CLI build**. A scratch hook marker or stream result remains outside the canonical source: there is still **no durable, privacy-safe, completeness-checked hook evidence delivery or no-tool heartbeat**. No Cursor activity extractor, published call or use denominator is enabled. |
| **Codex CLI 0.163.0**, skills and registry hooks | Across the recorded isolated skill runs, native `event_msg` items are `UserMessage`, `AgentMessage`, `Reasoning`, and tool events; there is no structured `SkillLoaded`/`SkillInvoked` item. A rooted developer inventory establishes project availability only. A pasted `$skill` mention or a SKILL.md file read can imitate apparent invocation. Scratch native `Stop`/`PreToolUse` hook completion was visible to the CLI, but the tested rollout did not persist a registry hook's configured command plus its execution outcome. | Keep skill loads/invocations and registry-hook runs **null/unsupported**, not zero. The verified MCP `McpToolCall` cell is independent of those signals. |
| **Kiro IDE 1.3.11**, separate from CLI | Standalone v1 hooks were registered, but no prompt/Stop marker appeared and the two new sessions reached the warehouse **only after manual reconcile**. The isolated IDE log contains `hooks.v2.executionDisabledUntrustedWorkspace` during the initial control. A later trusted-workspace control still did not establish hook execution or pre-reconcile delivery. | Registration, manual recovery and the later trust action cannot prove automatic delivery. Require a fresh, restarted trusted IDE workspace with hooks visibly enabled and a marker plus warehouse checkpoint **before** reconcile. Do not reuse CLI 2.32.0 hook or call conclusions for IDE 1.3.11. |

The temporary Kiro CLI probe used an agent profile whose tool list contained **only** the inert MCP server. `--trust-all-tools` was needed for the successful noninteractive control; the narrower `--trust-tools=@matrix-mcp-probe` did not grant approval in this CLI. It is **not** a proposed production setting. The Kiro probe hook script recorded only structural field names, alias and a one-way session digest in private `/tmp` files; it recorded no tool input/response. Cursor's scratch hook retained only structural keys, selected server/tool, strict result booleans and truncated one-way session/call digests; it never stored hook stdin, tool input/output, the `result_json` body, prompt or email. Cursor's temporary `--force` acceptance runs had scratch guards that denied shell, file-read and non-probe tools; the flag is **not** an installer or production setting. The additional aliases and probe hooks were removed from temporary configurations after the runs, preserving their original session-delivery hook. The current published matcher deliberately still returns `unsupported` for Kiro and Cursor.

### Required work before any PR readiness change

1. **Cursor temporary-home login and native signal controls are complete.** Its file credential store avoided the macOS login keychain; no credential was copied from the original home. Preserve its `sessionEnd` delivery hook, but do not publish a use cell before durable, complete, sanitized hook evidence is proven. The unmodified original checkout and `internal.observal.io` remain off limits.
2. Obtain a human-operated **trusted/restarted Kiro IDE** control. Inspect *execution*, not registration, then compare pre-reconcile warehouse state. Keep CLI/IDE runtime facts separate.
3. Choose a hook-evidence source design only after the native Cursor/Kiro controls, including authenticated session association, no-tool coverage, retry/replay, collision and missing-event behavior. A positive-only hook marker cannot be used as a usage-rate denominator. Never upload hook stdin, model output or tool arguments/results.
4. Run the applicable Linux full suite and matrix CI, audit the diff/screenshots and permissions, and obtain accountable human review of both stacked draft #3 and upstream draft #1779. The local focused suite and a loopback report do not make either PR ready.

### Documentation leads, not proof of the installed build

- [Cursor native hook events and fields](https://cursor.com/docs/hooks): the documentation led to the scratch test; the specific version's identity, call ID and three distinct result shapes above are **observed native runs**, not documentation alone.
- [Kiro hook triggers and MCP selectors](https://kiro.dev/docs/hooks/types/) and [legacy CLI 2.x/standalone hook placement](https://kiro.dev/docs/hooks/): the observed CLI hook alias is version-specific; V3's documented `mcp_<server>_<tool>` format is **not** evidence about CLI 2.32.0 or IDE 1.3.11.
- [Kiro IDE hook troubleshooting](https://kiro.dev/docs/hooks/troubleshooting/): check enabled state, tool matcher and the IDE output panel in the isolated portable workspace.
