# Remaining component-insights gates: Cursor, Codex, Kiro

**2026-10-17; stacked draft PR #3.** These are *conditional engineering estimates*, not support promises or evidence of zero use. They cover one tested version/scope at a time, including sanitized tests and isolated live acceptance, **after** necessary account or IDE access is available. Upstream product changes and CI/human-review time are not estimable. The verified-presence and permissions contract remains on draft #1779. No original home, original checkout, production endpoint, raw prompts, arguments, results, tokens, or transcripts were used as PR artifacts.

| **Cursor Agent 2026.10.14-941492e**, tracked project/user stdio pins | Reauthenticated only the temporary home using the CLI's file credential store. **Actual native hooks fired** in approved, rejected, server-error, no-tool and two-server/same-`ping` controls. `beforeMCPExecution` and `afterMCPExecution` supplied the exact server/tool, version, session/conversation IDs and the **same `tool_use_id`**; `postToolUse` carried the same ID but only `MCP:ping`, including on rejection/error, so it is **not** a success signal. | **Kiro IDE 1.3.11**, separate from CLI | Standalone v1 hooks were registered, but no prompt/Stop marker appeared and the two new sessions reached the warehouse **only after manual reconcile**. Require a fresh, restarted trusted IDE workspace with hooks visibly enabled and a marker plus warehouse checkpoint **before** reconcile. Do not reuse CLI 2.32.0 hook or call conclusions for IDE 1.3.11. |

The temporary Kiro CLI probe used an agent profile whose tool list contained **only** the inert MCP server. `--trust-all-tools` was needed for the successful noninteractive control; the narrower `--trust-tools=@matrix-mcp-probe` did not grant approval in this CLI. It is **not** a proposed production setting. The Kiro probe hook script recorded only structural field names, alias and a one-way session digest in private `/tmp` files; it recorded no tool input/response. Cursor's original scratch hook retained only structural keys, selected server/tool, strict result booleans and truncated one-way session/call digests. The new CLI collector persists only session/user/config/path hashes, server/tool, a full one-way call-ID hash, a strict outcome and receiver timestamp. It never stores hook stdin, tool input/output, the `result_json` body, prompt, email, command or URL. Cursor's temporary `--force` acceptance runs had scratch guards that denied shell, file-read and non-probe tools; the flag is **not** an installer or production setting. The additional aliases and probe hooks were removed from earlier temporary configurations. The new managed collector was exercised only in temporary project/user homes; those hooks and extra aliases were removed afterward, preserving the prior isolated project session-delivery hook. The current published matcher deliberately still returns `unsupported` for Kiro and Cursor.

### Required work before any PR readiness change

1. **Cursor temporary-home login, native signal controls, and a local sanitized journal/delivery slice are complete.** Its file credential store avoided the macOS login keychain; no credential was copied from the original home. The collector ran only in isolated homes and did not enable a server extractor or denominator. Do not publish a use cell until an independent server completeness check and matched/unmatched live reports pass. The unmodified original checkout and `internal.observal.io` remain off limits.
2. Obtain a human-operated **trusted/restarted Kiro IDE** control. Inspect *execution*, not registration, then compare pre-reconcile warehouse state. Keep CLI/IDE runtime facts separate.
3. Independently validate the new Cursor source on the server before any extractor opt-in: authenticated session/layer binding, no-tool coverage, retry/replay, collision, spoof and missing-event behavior. Kiro still needs its own trustworthy source and pairing design. A positive-only hook marker cannot be used as a usage-rate denominator. Never upload hook stdin, model output or tool arguments/results.
4. Run the applicable Linux full suite and matrix CI, audit the diff/screenshots and permissions, and obtain accountable human review of both stacked draft #3 and upstream draft #1779. The local focused suite and a loopback report do not make either PR ready.
